# VES Field

An offline-first progressive web app for recording GPS locations during VES surveys. It is a static site and can be hosted directly from GitHub Pages.

## Publish on GitHub Pages

In the repository settings, open **Pages**, choose **Deploy from a branch**, then select the branch and folder containing `index.html` (usually `main` and `/ (root)`). Once published, open the Pages URL on the phone. The first visit needs an internet connection so the app shell can be cached; afterward, projects and survey records remain available offline. GPS access requires HTTPS, which GitHub Pages provides.

On Android, use the browser's **Install app** prompt or **Add to Home screen**. On iPhone, use Safari's **Share → Add to Home Screen**.

The app name, connection status, and running version are shown at the bottom of the screen. After publishing a new version to GitHub Pages, the browser checks for it and **Update app** appears at the top when the new service worker takes control. Tap it to reload the updated app. The button cannot publish source changes that have not yet been deployed. If there is no connection, the installed version remains available offline and no update can be detected until the app reconnects.

## Working with projects

The app opens to the point-acquisition screen, which immediately shows the live GPS position. Select a project and site, then choose a station to see distance and azimuth relative to the station coordinates and enable A/B point capture. The selectors collapse after selection; tap **Change** to reopen them and see their UIDs. The current project, site, and station selections are saved on the device and restored when the app reopens; **Finish** deselects the station and returns to the station dropdown without deleting data. Use **Create New** next to a selector to add a project, site, or station, or **Create New Station** for the first station at a site. New projects are named **VES Project 1**, **VES Project 2**, and so on by default, continuing after existing default-named projects. Expand **Points** below the map for point history, or expand the station selector for its coordinates and setup. A new station requires coordinates: the dialog tries GPS automatically, and you can enter coordinates manually or use **Get GPS fix**. Manually entered coordinates have no GPS accuracy. Older or imported stations without coordinates still prompt for setup before point capture. Use **Station setup** from acquisition or station browsing to change the station name, enter latitude/longitude manually, fill them from GPS, and edit target azimuths A and B. While entering target azimuths, the app shows the smallest angle between A and B; acquisition shows the current azimuth alongside the selected target. Coordinates are validated as decimal degrees (latitude −90 to 90, longitude −180 to 180); setup changes require confirmation. Each captured point stores its timestamp, coordinates, GPS accuracy, distance and azimuth from the station, and selected target.

When a station with coordinates is selected on the acquisition screen, use **Share QR** to display its project/site/station IDs and station setup. QR sharing is unavailable until station coordinates are set. On the other device, choose **Scan QR** and scan the displayed code. Review and confirm the current and resulting project, site, station, and target before linking. Missing project/site/station structure is created using those same IDs, including station coordinates and target azimuths; existing records remain intact, and the receiving device selects the opposite A/B target. Any replacement of saved coordinates or azimuths is shown in the confirmation. The code includes hierarchy names, station coordinates, target azimuths, and the sender's selected A/B side, but not acquired points. QR creation and scanning work offline; camera access requires browser permission and a secure origin such as the HTTPS GitHub Pages site. The scanner defaults to a rear camera and offers a camera selector when the browser exposes multiple cameras; some lenses may not be listed. It requests continuous autofocus when supported; tap the camera preview to refocus on devices that support tap-to-focus.

Use **Browse records** to review projects and sites. Returning to acquisition preserves the previous project, site, station, and target, unless they were deleted. Opening a station shows its acquired-point list and **Station setup**, the same editor available during acquisition. Enter decimal-degree coordinates directly or use **Get GPS fix** to fill both coordinate fields from a GPS fix; edit target azimuths in that editor as well. Changes require confirmation before they are saved. Choose **Acquire points** to return to the capture screen with the browsed station selected instead. The capture screen also shows the station's point history. GPS operations reuse a very recent live fix when available; otherwise, getting a high-accuracy fix can take several seconds, and the app shows a progress indicator while it waits.

The north-up field map plots station coordinates, current GPS position, recorded points, and both target directions over a north/east coordinate grid. Grid interval and scale adjust to include the most distant plotted position. When a heading is available, a compact compass rotates its north marker with the device and shows the selected target relative to the device's heading; a heading marker also appears at the current position. Compass starts automatically where supported. Some browsers require permission from a button and cannot determine hardware availability before permission is granted. If no heading arrives, the app reports the compass as unavailable; a later heading will still be displayed. If the browser only provides relative orientation rather than a north-referenced compass heading, the map labels it as approximate.

To conserve power, live GPS and compass updates stop while browsing records or when the app is hidden, and resume on the acquisition screen. The QR camera closes when the app is hidden. Live acquisition still uses high-accuracy GPS; leave the acquisition screen or lock the phone when not taking measurements. Actual battery savings depend on the device and browser.

Map colors distinguish the station (green), current position (black), target A (cyan), and target B (magenta with a dashed direction line).

Use **Export CSV** to download a project-wide table with rows for every station, station coordinates, and recorded point; the default filename is the project name with a `.csv` extension. **Share / sync** sends a versioned project JSON file using the phone's share sheet where supported; otherwise it downloads the file. The default filename is the project name with a `.vesfield.json` extension. Import that file on another device to merge records with the same project ID. This is an offline file-transfer workflow, not live synchronization.

Project, station, and individual recorded-point deletion each require confirmation before removing local data. If the system share sheet denies access or sharing is unavailable, the app automatically downloads the project file instead.

### Bluetooth limitation

Browser PWA APIs do not let a web app act as a Bluetooth LE GATT server. Direct BLE phone-to-phone synchronization therefore requires a native app or a separate BLE device/service. On supported phones, the system share sheet may offer Bluetooth as a way to send the exported project file, which can then be imported by the receiving device.

## Local data and privacy

Project data is stored in the browser's IndexedDB on the current device. It is not uploaded to a server. Clearing browser/site storage removes the local copy, so export/share backups before clearing it or changing devices.
